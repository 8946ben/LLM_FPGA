优化前：单累加器 + 顺序行循环（历史基线）

综合最大 1,097,890,446 拍 ≈ 10.979 s @ 100 MHz；实测 run_seconds 11.090 s。红色虚线 = 三大瓶颈。

II=8（achieved） 12.5 MMAC/s 上限 DSP 仅 5 / 2520 vocab_loop 顺序执行

  • 权重 151,936 × 896 FP16（272,269,312 B ≈ 259.66 MiB）常驻 DDR，每次 token 仍需全量重扫；权重上传为一次性冷启动（历史 ≈ 7.692 s，--load-weight）。
  • 4 个 gmem bundle 汇入同一 HP0（128-bit @ 100 MHz，峰值 1.6 GB/s），并非 4 条独立 DDR 通道。
  • 点积循环依赖单个 FP32 累加器（HLS 200-880）：target II=1、achieved II=8 → 每 8 拍才 1 次 MAC，12.5 MMAC/s 上限，与实测 ≈ 12.28 MMAC/s 吻合。
  • vocab_loop 顺序执行、未流水：≈ 7,226 拍/行 × 151,936 行 → 综合最大 1,097,890,446 拍 ≈ 10.979 s；实测 run_seconds 11.090 s。
  • hidden_cache 为单端口 BRAM；权重通路外部 32-bit、按单个 FP16 逐元素取数（已有 burst，实际事务待总线测量）；DSP 仅用 5 / 2520，反映并行度低。

优化后：128-bit 读 + 8 lanes + 交错累加 + 数据流（P2 目标架构）

理想计算下限 0.170 s @ 100 MHz（工程目标 0.3 ~ 0.6 s）；P3 提频 200 MHz 后理想 0.085 s（需实现时序与带宽验证）。

U=8 lanes K=16 交错累加 word 循环 II=1 乒乓 tile 双缓冲 DATAFLOW 重叠

  • 数据流四阶段重叠：A 顺序 burst reader（每拍 1×128-bit word = 8×FP16，按位 bit-cast）→ 乒乓 tile 双缓冲（32 行 ≈ 112 KiB）→ B 8 lanes 乘加 + partial[8][16] 交错累加 → C 流水归约树 → D penalty / argmax。
  • 依赖消除：lane j 只写 partial[j][i mod 16]，同一单元间隔 16 拍 ≥ 反馈延迟 → word 循环 II=1（每行 896 half = 112 word）。
  • hidden 缓存 cyclic 分区 ×8（8 banks），每拍供 8 个 half 与权重对齐；行末 128 个 partial 流水归并，与下一行点积重叠。
  • burst len=16 / outstanding=16 起步（HP 会拆分 >16 拍 burst），以实测有效 GB/s 为准；理想下限 0.170 s @ 100 MHz。
  • 数值一致性是验收条件：交错累加 / 归约树改变 FP32 求和顺序，必须与基线对拍；FP16 平局保留较小 token ID（如 step7 的 100013 与 100048 同分）。

公式与一致性校验

文档 §3 的模型：

Tcompute ≥ 136,134,656 × I / (U × f)
Tmemory　≥ 272,269,312 / BW有效
Tkernel　≥ max(Tcompute, Tmemory) + 尚未被重叠隐藏的开销

  • 基线一致性：136,134,656 × 8 ÷ 100 MHz = 10.891 s，与综合最大 10.979 s 相差 ≈ 8.81M 拍 ≈ 58 拍/行（行级 / 边界开销，推算）→ II=8 是主因的判断成立。
  • P2 双下限重合：计算 17,016,832 拍 = 272,269,312 B ÷ 16 B/拍 —— 100 MHz 下计算与 HP0 理论带宽同时压线，因此必须读算重叠（DATAFLOW），且实效带宽决定成败（0.8 GB/s → 340 ms）。
  • P3：8,508,416 拍 @ 200 MHz；若有效带宽 1.5 ~ 2.5 GB/s，读权重 109 ~ 182 ms（文档 §5 P3），需实现时序同时达标。

总线与端口连线：控制面 AXI4-Lite + 数据面 AXI4（HP0）

连线与端口号摘自 realFpga/vivado/create_lm_head_axu9eg_bd.tcl（L49–171）；内核侧接口见 lm_head_kernel.cpp（L40–62）。箭头方向 = 主设备发起（请求）方向；读数据沿原路反向返回。

  • 两条路径职责分离：参数 / 启动 / 轮询走 AXI4-Lite（轻量、无 burst、寄存器级）；批量数据走 AXI4（burst 突发）。
  • HP0 非一致性：PL 与 A53 cache 不自动一致——权重常驻不变时无需每 token flush，hidden / logits 方向需软件维护一致性（§4.5）。
  • HP 口流量整形：会拆分 >16 拍的 burst，内核发出的长 burst 到 HP0 侧变成更多小事务（§9，AMD wiki）。
  • 4 个 m_axi 在 SmartConnect 汇聚为一个 HP0：带宽按总和竞争，weight 束是绝对主导；位宽 32→128 在此转换。
  • 时钟链：PL0_REF_CTRL（100 MHz，DPLL）→ ap_clk / SmartConnect aclk / saxihp0_fpd_aclk；P3 提频必须整链同步核对。
  • P4 扩展路线：将部分权重流量分到第二个 HP 口（如 HP1）开第二扇门，但 PS 互连与 DDR 控制器仍共享，不保证线性加速。

FIFO 解耦原理：切断时序依赖 / 吞吐依赖（交互演示）

配置按问答给出：H=896，8 lanes，112 word/token，ACC_INTERLEAVE=16，context FIFO 256-bit × 32（= 2 个 token）。箭头/格子为原理演示；对话原文写 BF16，本项目权重为 FP16（同为 16-bit，8×16=128-bit 结论一致）。

① 物理时序解耦 —— 切断的是组合路径，不是逻辑依赖
点积加法器━━ 同一拍内：乘法 → FP32 累加 → 传递 → 归约加法 ━━▶归约加法器路径长 → 建立时间难收敛 → 频率上不去
点积阶段──▶ 写 FIFO（周期 N）BRAM / 寄存器 / FIFO 控制读 FIFO（周期 N+k）──▶归约阶段两段各自满足自己的建立时间，可分别优化

切断的是“直接组合路径 + 同周期完成要求”。逻辑依赖仍在：归约必须等点积结果；FIFO 的 empty / full 仍构成控制依赖——空则消费者等待，满则生产者暂停。

② 吞吐解耦 —— 只吸收短时波动，不改长期瓶颈

FIFO 可吸收：DDR 返回延迟 · AXI burst 边界停顿 · FP32 加法 / 归约树流水延迟 · 控制状态机间歇 · 双方启动时间差。但若归约长期更慢，FIFO 终将填满并反压暂停点积，因此：

稳态吞吐 = min( 点积吞吐，归约吞吐，访存吞吐 )

下面的模拟器可验证：把归约调慢 → FIFO 逐渐填满 → 点积被反压 → 总吞吐收敛到归约速率；打开 DDR 抖动 → FIFO 吸收停顿，慢归约场景下吞吐完全不变。

上下文组织与两级 FIFO

一个 token 的 16 个 context slice（256-bit / 个）
点积完成 112 word 后，每个 lane 留下 16 个 partial；硬件把同一 slot 的 8 个 lane 打包成一个 slice 写入 FIFO
FIFO 宽度 = 8 × FP32 = 256 bit；每 token 写 16 个 slice；深度 32 → 32 / 16 = 2 个 token 的缓冲
两级 FIFO 各管一段
DDR / AXI──▶weight_fifo──▶点积阶段（partial[8][16]，II=1）──▶context_fifo 256×32──▶归约阶段（8 路求和 + 树）──▶FP16 logit
  • weight_fifo：隐藏 DDR / AXI 权重读取延迟，解耦访存与计算；
  • context_fifo：解耦点积与归约，深度 32 ≈ 缓存 2 个完整 token 的上下文，即使归约短暂停顿点积也不必立刻停止；
  • partial[8][16]：解决点积内部的 FP32 加法反馈依赖（II=1 的来源）。

归约阶段读出一个 token 的 16 个 slice 后：sum_lane[j] = partial[j][0] + … + partial[j][15]（8 路并行），再 logit = sum_lane[0] + … + sum_lane[7]。FIFO 中保存的是部分和，不是最终 logit。

口径注记：本页参数（ACC_INTERLEAVE=16、context FIFO 256-bit×32、weight_fifo / context_fifo 两级划分）来自问答给出的配置，作为架构原理演示；对话原文中的 BF16 对应本项目 FP16（位宽相同）。文档 §5 P2 所述“双组 partial、归约与下一行重叠”即该解耦机制的目标效果；具体 FIFO 深度/宽度以实际 RTL 为准。
