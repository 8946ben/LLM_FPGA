02 / THE MATH

核心计算公式

看起来是 1.36 亿个权重，原理却只是一组重复的乘加。FPGA 的价值是把规则、重复的运算变成并行硬件流水线。

LM Head：矩阵乘向量

对词表中的每个 token v，都计算它与 hidden 的点积：

z[v] = Σi=0895 W[v,i] × h[i]

h 是 896 维隐藏状态，W 是模型权重，z[v] 是 token v 的原始分数。

随后三步

  1. 转成 FP16：保持和 trace 的 LM Head 输出精度一致。
  2. 重复惩罚：历史 token 的正分数除以 1.1，负分数乘以 1.1。
  3. argmax：选最大分数；平分时保留编号较小者。
h = [896]
最后位置的 hidden
W = [151936,896]
约 1.36 亿个 FP16 权重
z = [151936]
每个 token 一个分数
token = uint32
正常只返回 4 字节 ID
为什么没有 bias？ Qwen2.5 此处共享 embedding 权重作为 LM Head 投影，没有额外 bias；我们导出的是 model.embed_tokens.weight。

HLS

RTL

06 / PRECISION

FP16 的关键陷阱

第 7 步两个候选在 FP32 略有差别，但转成 FP16 后相等；argmax 放在转换前后会选出不同 token。

FP32 累加结果

A = 20.20183
B = 20.205446

B 略大，立即 argmax 会选 B。

→

转换为 FP16

A = 20.203125
B = 20.203125

成为平局；稳定 argmax 选较低 ID 100013，与 trace 一致。

结论：点积可用 FP32 累加，但必须先得到架构规定的 FP16 raw logits，再做 repetition penalty 与 argmax。
07 / PERFORMANCE

算对，不等于算得快

当前核刻意先做最简单的串行正确性基线。资源很少、容易验证，但约 3.299 秒/token，不是最终方案。

3.299 s全尺寸综合估计 / token

数字如何得到？

824,709,518 cycles × 4 ns ≈ 3.299 s。

瓶颈：FP32 accumulator 有循环依赖，下一次加法要等上一次结果，因此点积 II=6；同时乘加单元太少。

09 / REAL BOARD

真实上板还差什么

当前完成的是可信仿真基线。板卡阶段不是推倒重来，而是把已验证的层按实际硬件接起来。

确定板卡

准确 FPGA part、DDR/HBM、网口速率和厂商 shell。

设计性能架构

PE 数、权重分片、AXI 宽度、累加树和缓存。

生成 bitstream

综合、布局、布线、真实时序收敛，最后生成配置文件。

接入网口服务

根据平台使用板上 CPU、XRT 或厂商 TCP/IP 数据路径。

逐级点亮

先 PING，再权重，再合成向量，最后 8 个真实 trace。

测量稳定性

延迟、吞吐、带宽、温度、功耗和长时间错误率。

10 / FAQ

常见问题

第一次接触 FPGA 时最容易混淆的几个边界。

仿真是不是意味着 FPGA 真的运行了？

不是。C 仿真运行 C++，RTL co-sim 运行 Verilog；只有 bitstream 下载到板卡并经过真实接口才叫板级运行。

为什么综合通过还要 RTL co-sim？

综合证明能生成硬件并给出估计，不自动证明 RTL 输出等于 C。co-sim 用同一测试台对拍。

为什么不在 RTL 里跑完整 260 MiB 权重？

RTL 仿真逐周期运行，非常慢；Vitis 2021.1 还会生成约 1.2 GiB 文本向量。全量数值交给 C，小尺寸检查 RTL，是合理分层。

m_axi 与 AXI-Lite 有何区别？

m_axi 是 tensor 的高速货运通道；AXI-Lite 是写地址、尺寸、开关和启动命令的控制通道。

为什么权重只上传一次？

权重约 260 MiB，而 hidden 只有 1792B。权重应驻留板上内存，每 token 只传变化的数据。

bitstream 是什么？

配置 FPGA 逻辑、资源和连线的文件。HLS 生成 RTL 后还要布局布线才能生成它。
