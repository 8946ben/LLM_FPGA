# lm_head v4 后续实施规划 · 2026-10-26

当前主线为冻结的动态部分通道 d64 / Top4096 / B1024 / 双份 BF16 权重。现有质量门槛为整体及中文、英文、代码、数学各类 decode 赢家召回均不低于99%；数值实现仍要求逐位一致。已有质量结果保留，本阶段验证硬件实现与实际性能，不重新拟合或选择参数。

## 当前起点

- 原完整CoSim Fail根因已由最小SV及全部151936个预览值重建确认：XSim2022.2动态字节数组的512MiB地址别名。该Fail保留。
- 隔离分bank仿真内存已通过512别名对及2093条实际事件独立回放。32/128位、X/Z、批量访问和越界检查已覆盖。
- 原完整34105344拍TV重建的两份权重SHA正确。前5块已独立审计通过：1522模型边界字节、40960权重拍、64通道、5120 raw/key全一致；原133源及RTL/压力身份未变、所属组空、无锁。
- 被动阶段计时器、AXI范围观察器及原C后检查正负控制通过后，已手动启动修复模型下的一次完整验证；最新保存阶段EXECUTING_XSIM。四门槛及源SHA冻结，尚无完整返回数组或FIFO结论。
- 选择器13例RTL、原Csim及HLS估计通过；完整联合RTL、新200MHz实现和板卡性能仍未取得资格。

## 仿真成本安排

1. 前5块及独立VCD回放已完成，不重复；当前只保留已有的一次完整生成XSIM/C后检查，不并行第二份完整验证。
2. 边界、排序、AXI背压和状态切换尽量采用有限分段用例；完整配置验证用于检查真实阶段衔接。
3. 原0～256拍随机停顿是强压力条件。保留强压力验证的独立身份；性能测试另建明确条件，不把强压力总周期作为正常DDR或FPGA decode效率。
4. 不默认对每个输入重跑一遍耗时数十小时的完整强压力调用。先冻结完整/分段测试矩阵、终止条件、工具身份和输出范围，再手动启动。
5. 部署/运行XSim模型时保留大于512MiB地址别名回归。只修改隔离副本，避免生成流程重新覆盖内存修复而未被发现。

## decode效率如何报告

- 本模块主指标：M14单次生产调用耗时median/P95，及M14等效输出率。单次输出一个token时，`等效token/s = 1000 / median_ms`。
- 对照加速比：`v3.1 median_ms / v4 median_ms`。两者必须使用可比计时范围、时钟、DDR/AXI条件、hidden/history和生产模式；历史v3.1记录与本轮同板重测分列。
- FPGA报告同时给IP周期计时、A53调用墙钟和必要的数据准备开销，明确哪些计入一次decode。
- 首次权重加载作为启动开销单列。它不等于TTFT；没有完整LLM推理链的端到端测量时，不将M14输出率写成整网decode速度，也不填造TTFT。
- 原GPU557配置图继续作为软件研究依据。FPGA数据另列测量条件和实测标识，不用GPU倍率或逻辑字节数代替硬件加速比。
