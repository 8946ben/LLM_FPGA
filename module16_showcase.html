PART 01

模块 16 有哪些运算，每一步运算量如何

模块 16 是 Qwen2.5-0.5B-Instruct 的最后一个模块：把 24 层 Transformer 输出的最终 hidden state 映射到 151,936 维词表 logits，并完成 greedy argmax 选出下一个 token。权重与 Embedding 共享（tie_word_embeddings）， 即 model.embed_tokens.weight，shape [151936, 896]，FP16。

运行时系统结构（上位机 / PS / PL 数据关系）

数据通路要点：PL 不直接连网口——上位机只与 A53 上的 lwIP 服务通信；所有数据（权重 / hidden / 位图 / logits） 都先落到 PS DDR，PL 内核经 S_AXI_HP0_FPD 高带宽口访问 DDR；控制走 M_AXI_HPM0_FPD → AXI-Lite。 每个 token 的计算结果只有 8 B 回传，260 MiB 权重只加载一次、常驻 DDR 复用。

PART 02

从 C 代码到上板可运行，做了哪些工作

一条「correctness-first」的完整闭环：先有 golden trace 和 CPU 参考，再逐级仿真、综合、集成、 裸机网络服务，最后在真实板卡上用 8 步真实生成 trace 验收。全程工具链 Xilinx 2021.1。

Python 参考与 golden tracePyTorch

插桩版 model.generate(do_sample=False) 导出完整 trace（prefill + 7 decode 步）；CPU 参考实现 matmul + penalty + argmax，8/8 与 trace 对齐（max abs ≤ 0.0078，cosine = 1.0）。反算确认 trace 的 generation scores 含 repetition penalty 1.1（1.1 时 8/8 PASS，1.0 全 FAIL）。

权重导出与 fixture 准备tools/*.py

纯 NumPy 读 safetensors，BF16 → FP16 导出 260 MiB 权重（SHA-256 存档）；每步 trace 压缩为 4 个紧凑 fixture 文件（hidden / golden logits / history 位图 / expected token）。

HLS C 仿真Vitis HLS · csim

全尺寸（151936×896）一次加载权重连跑 8 步：token 8/8 匹配，max abs ≤ 0.015625，cosine 全 1.0，Top-5 全 5/5。

C 综合csynth

目标 200 MHz，估计 Fmax 273.97 MHz；BRAM 14/1824、DSP 5、LUT 5816/274080。定位为功能基线（串行点积 II=8），明确把性能优化放到正确性验收之后。

RTL 协同仿真cosim · XSim

用 -DLMH_COSIM_SMALL 4×4 同构核规避 260 MiB 权重生成超大测试向量，Verilog 级 cosim PASS（1/1 事务）。

IP 导出ip_catalog

导出 VLNV xilinx.com:hls:lm_head_argmax:1.0（4×m_axi 32-bit + s_axilite 控制）。此处踩中 2021.1 在 2026 年的 core_revision 32 位溢出坑，固化兼容脚本解决（见第三部分）。

Vivado Block Design 与比特流Vivado 2021.1

控制通路 M_AXI_HPM0_FPD → s_axi_control @ 0xA0000000；4 条数据 m_axi → AXI SmartConnect → S_AXI_HP0_FPD → PS DDR。PS/DDR/GEM3 配置与同事已验证的 RMSNorm 工程逐项对齐（1111 项 PSU 参数仅 1 项无害差异，psu_ddr_init_data() 523,694 字符逐字节一致）。结果：WNS +4.262 ns / TNS 0 / WHS +0.010 ns，DRC 0 error。

Vitis 裸机平台与 lwIP TCP 服务A53 standalone

从 XSA 建 standalone 平台，BSP 调大 lwIP 内存参数以承载 260 MiB 分块上传；A53 裸机实现 LMH1 协议服务端（TCP 19016 端口）：24 字节帧头 + CRC32，opcode = LOAD_WEIGHT / RUN_TOKEN / PING，含分块状态机、offset 连续性检查、DCache Flush/Invalidate、HLS 驱动轮询。DDR 专用 .lmh_buffers 段 64B 对齐、互不重叠。

网口逐级点亮（H-1 → H-8）真实板卡

JTAG Hello World → ping/TCP → AXI-Lite 寄存器读写 → 4×4 合成用例（含 penalty 改变 Top-1、同分取小 ID 两个专项）→ 分块上传与错误帧负例 → vocab 128→1024→8192→65536 分档扩大 → 完整 260 MiB 权重 → 8 步真实 trace。

PART 03

遇到的难题，以及如何解决的

上板过程共记录 67 条调试日志（realFpga/DEBUG_LOG.md）。时序、资源、数值精度都不是障碍—— 真正的硬骨头是一个复位电平接反导致的整机锁死，和一系列工具链「假成功」陷阱。

难题一（最大）：启动 HLS IP 后整机锁死，只能物理断电

现象：第一次 RUN_TOKEN 后板卡从网络上消失

现象

TCP 连接被 reset，随后 ping 不通、A53 无法 halt，JTAG 经 DAP 读 HLS 寄存器报 AXI AP transaction error；任何软件复位/重新配置 PL 均无效，只能物理断电重启。

排障

先怀疑复位拓扑（peripheral_aresetn 同时接 SmartConnect 和 IP），按同事工程修正后复测仍锁死。改用「不启动内核的 AXI-Lite 预检」：只读 AP_CTRL、写读 hidden_size，绝不写 ap_start，并绕过 A53 直接走 DAP。结果连第一次读 AP_CTRL 就超时——证明控制总线在内核启动前就不响应，排除计算/DDR/Cache 因素。

根因

proc_sys_reset 的 C_AUX_RESET_HIGH=0（aux_reset_in 低有效），而 BD 脚本把常 0 接到了 aux_reset_in —— 等于永久请求复位，SmartConnect 与 HLS IP 的复位永远无法释放。同事的参考工程里该端口未显式连线，由 Vivado 自动补成常 1，纯看 BD 图根本发现不了。

解决与验证

修复

BD 脚本改为 const_one → aux_reset_in、const_one → dcm_locked、const_zero → mb_debug_sys_rst，并加注释防止再次把有效电平理解反。

验证

重上电后预检通过（AP_CTRL 读出 ap_idle=1，hidden_size 写读一致），4×4 四个计算用例全 PASS，锁死不再复现，直至 8/8 验收通过。

难题二：Xilinx 2021.1 工具链的「假成功」陷阱（2026 年使用老工具链）

陷阱现象对策
core_revision 32 位溢出HLS 把 2026-07-24 编成 2607241639 写入 IP 版本号，超过 signed 32-bit，IP 生成失败改自动生成的打包脚本 Revision 为 "1"，固化 run_export_ip_2021_compat.ps1
退出码不传播日志明确报 Failed to generate IP，但 Windows 下 vitis_hls.bat 的 $LASTEXITCODE 仍为 0验收条件 = 退出码 + 产物文件（component.xml）实际存在
XSCT 构建静默失败输出 BUILD_PASS、退出码 0，但 Debug/ 下没有 ELF——后台构建通道已断开，根本没跑改为直接 make；验收条件加「ELF 存在且非零 + map 文件存在」
BSP regenerate 覆盖补丁每次 regenerate 把修复过的 PHY 驱动（xemacpsif_physpeed.c）还原为 Xilinx 原版Tcl 脚本固化「regenerate 后自动重打补丁 + 校验标记/SHA-256」
lwIP 内存参数约束调大缓冲区后 platform generate 失败：MEMP_NUM_TCP_SEG 必须 ≥ TCP_SND_QUEUELEN按约束公式反推，定为 MEM_SIZE 256 KiB / SND_BUF 32 KiB / TCP_SEG 512
方法论沉淀：不看退出码，看产物哈希与独立验证标记。每一阶段的 PASS 都由独立脚本复核产物 （文件存在性、SHA-256、报告中的关键字段），工具自己打印的 PASS 一律不作为验收依据。

难题三：协议层 —— 错误帧还没发完连接就被 reset

现象

上位机发非法 opcode，服务端把错误帧交给 lwIP 排队后立即关闭连接，客户端先收到 RST 而非错误帧（ConnectionResetError）。

根因

tcp_write 只是排队，数据尚未真正发出并被对端 ACK。

修复

新增发送确认计数：由 tcp_sent 回调累计 ACK 字节，错误响应 header+payload 全部被确认后才关闭连接。修复后 5 项协议冒烟（半帧头/粘包、未加载权重先运行、同连接多帧、CRC 错误恢复、非法 opcode）全部 PASS。

难题四：数值与验证口径的三个暗坑

暗坑说明处理
FP16 归约顺序差异FPGA 逐项顺序累加与 GPU GEMM 归约顺序不同，产生约一个 FP16 量化步长的误差实测最坏 0.015625，稳定小于 0.02 门限；以 Top-5 / top-1 token 一致性作为判据，而非强求 allclose
argmax 必须在 FP16 域做step 7 两个 token 转 FP16 后同为 20.203125，在 FP32 累加器上 argmax 会选错硬件复现 torch.argmax「同分取较小 ID」规则，与 trace 逐 token 对齐
验证陷阱：只比 token 无法证明 penalty 生效该 trace 8 步恰好 raw Top-1 == processed Top-1，penalty 开关结果一样用 step 2 的 score 值证明：关 = 30.046875，开 = 30.046875/1.1 ≈ 27.315，确认开关真实传到硬件

PART 04

后续优化方向

当前 11.09 s/token 是正确性基线，不是性能目标。瓶颈非常明确：单累加器串行点积（II=8）+ 32-bit AXI 权重读带宽。资源余量巨大（DSP 用了 5/2520），优化空间完全打开。

模块 16 自身的性能路线（按优先级）

① 多 PE 并行点积 + 分 bank 累加

当前单累加器 FP32 依赖链导致 II=8，是最大瓶颈。权重按 token 行分片，多 PE 并行、分 bank 累加消除 II=8。ZU9EG 有 2,520 个 DSP，目前只用了 5 个。

② AXI 数据通路扩宽

4 条 m_axi 目前均为 32-bit，是为首次上板保功能的选择。扩宽到 128/256-bit 直接成比例提升权重读带宽（该算子是带宽受限型）。

③ 时钟 100 MHz → 200 MHz

HLS 估计 Fmax 273.97 MHz，当前 bitstream 保守跑 100 MHz。功能稳定后切 200 MHz 并完整回归（bring-up 计划阶段 I）。

④ 权重驻留与多通道

260 MiB 权重现驻留 PS DDR4（4 GB/64-bit）；板载另有 PL DDR4（2 GB/32-bit）。驻留位置与多 DDR 通道拆分待评估。

模型级路线

方向内容验收口径
量化先 FP16/BF16 对齐 → W8A8/INT8；W4A8 明确不作为第一阶段目标cosine ≥ 0.99，Top-5 overlap ≥ 80%
其余模块上板模块 0~15 中 RMSNorm（同事已有同板验证工程）、QKV、RoPE、KV Cache、Softmax、SwiGLU MLP、残差等尚未接入统一 trace逐模块与 golden trace 对齐，同模块 16 的三阶段流程
层融合 / 流水先用 PS 调度 + DDR buffer 串联各 IP，热点稳定后再做 attention/MLP 层融合（99_fused_layer 预留）；不一开始硬连 AXI-Stream单层 block → 24 层串联 → 完整 prefill/decode + KV cache
更大模型迁移0.5B 闭环后迁移更大 Qwen2.5，需替换权重、结构参数、golden trace 与 kernel tile 参数同一套 LMH1 协议与验证方法论复用
模块 16 的意义：它是整条推理链的最后一个模块，却不依赖任何上游 FPGA 模块 （上位机直接喂保存好的 hidden），因此被选为第一个打通「HLS → Vivado → 裸机网络服务 → 真实板卡验收」 全链路的模块。这套流程、协议、调试方法论和避坑清单（DEBUG_LOG 67 条）将直接复用到后续全部模块。

APPENDIX

术语速查（结合本工程）

阅读本页时涉及的 FPGA / HLS 名词，统一在这里结合模块 16 的实际情况解释。

基础概念

HLS（High-Level Synthesis，高层次综合）

用 C/C++ 写算法、由工具自动转成 RTL 硬件的流程：C++ 源码 →（HLS 综合）→ Verilog →（Vivado）→ bitstream。本项目用 Vitis HLS 2021.1，把 lm_head_kernel.cpp（C++ 的 for 循环 + 浮点运算）综合成 lm_head_argmax IP 核。同一份 C++ 可先在 PC 上做 C 仿真对齐 golden trace，再综合成电路，不用维护两套实现。硬件意图通过 pragma 表达，如 PIPELINE II=1、ARRAY_PARTITION。

PE（Processing Element，处理单元）

一个独立完成乘加运算的计算单元（乘法器 + 累加器）。PE 不是芯片固定资源，是用 DSP/LUT 搭出来的。当前内核只有 1 个 PE（单累加器串行点积，耗 5 个 DSP）；优化方向就是铺几十个 PE 并行。ZU9EG 有 2,520 个 DSP，理论可容纳上千个 FP16 PE。

II（Initiation Interval，启动间隔）

流水线每隔多少个时钟周期能接受一个新输入，II=1 为满分。当前点积 II=8：因为 acc = acc + W[k]*h[k] 下一次累加依赖上一次结果，而 FP32 加法有 8 拍延迟，乘法器 7/8 时间在空等。消除方法：拆成多个部分和累加器轮转（每个累加器两次使用间隔 8 拍，正好盖住延迟），最后再归约求和。

bank（存储体 / 存储分区）

FPGA 一块 BRAM 每拍只能提供 1~2 个访存端口。多 PE 同时读同一块 BRAM 会端口冲突，因此把数据按规律拆到多块独立 BRAM（ARRAY_PARTITION），每块有独立端口，N 个 PE 同拍各读各的——存储带宽才能与并行度匹配。

DSP（DSP48E2 切片）

FPGA 里的专用乘加硬件单元，是矩阵乘的主力资源（LUT/FF 是通用逻辑，BRAM 是片上存储）。ZU9EG 有 2,520 个，当前只用了 5 个（0.2%）——资源占用低是串行单 PE 架构的结果，不是"性能好的证据"，恰恰相反：材料闲置 99.8%。

PS / PL / A53

Zynq MPSoC 芯片 = PS（处理系统，固化在芯片里的 ARM 处理器 + DDR 控制器 + 外设）+ PL（可编程逻辑，即 FPGA 部分）。Cortex-A53 是 PS 里的 ARM CPU（ZU9EG 有 4 核，本工程用核 0 跑 standalone 裸机 + lwIP 服务端）。上位机数据先进 A53，再由 A53 调度 PL 侧的内核。

本工程的总线接口

m_axi 与 s_axilite（内核的两种口）

HLS 给内核生成两类接口：m_axi（AXI 主口，内核主动读写 DDR 的高速数据口，本内核有 4 条：hidden / weight / history / logits）和 s_axilite（AXI-Lite 从口，低速控制口，PS 通过它写参数、写 ap_start、读 ap_done/token/score，基地址 0xA000_0000）。

AXI 主（master）/ 从（slave）

主发起读写请求，从响应请求。本链路：内核 m_axi = 主；PS 的 HP0 口 = 从；SmartConnect 居中，面朝内核的一侧是从口、面朝 PS 的一侧是主口。

AXI SmartConnect「4 从 1 主」

汇聚互联 IP：4 个从口分别接内核 4 条 m_axi，1 个主口接 PS 的 S_AXI_HP0_FPD。内部做地址译码（4 路请求落到同一 DDR 空间的不同基地址：weight@0x4000_0000 等）和仲裁（多口同时请求时排队，weight 口流量占绝对主体）。相当于"4 进 1 出的漏斗 + 交警"。

HPM0 与 HP0（PS 上的两种 PL 接口）

M_AXI_HPM0_FPD：PS 做主、PL 做从的控制口（A53 → 内核 s_axilite，低速）。S_AXI_HP0_FPD：PL 做主、PS 做从的高带宽数据口（内核 → PS DDR，承载 260 MiB/token 的权重读取）。命名里 M/S 表示该口在 PS 侧扮演的角色。

数据流里的两个细节

history bitmap（"+bitmap"）

repetition penalty 需要知道哪些 token 出现过：用一个 bit 表示一个 token id 是否在历史中，151,936 bit ÷ 32 = 4,748 个 uint32 = 18,992 B。上位机构建后随 RUN_TOKEN 上传；内核对每个 logit 查对应 bit，历史 token 正分 ÷1.1、负分 ×1.1。仅在开启 penalty 时传输（所以图上标"+"、"可选"）。

PS → PC 的两条回传路径

token + score（8 B）：不经过 DDR——内核写进自己的 AXI-Lite 寄存器（0x68/0x78），A53 轮询到 ap_done 后经 HPM0 直读。raw logits（303,872 B，可选）：经过 DDR——内核经 m_axi/HP0 写入 DDR，A53 做 DCache Invalidate 后读出，再经网口发给 PC。
