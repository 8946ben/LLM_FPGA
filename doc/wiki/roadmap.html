设计前的六条核查结论

#结论对设计的影响
一当前最大浪费不只是接口窄，还有无效计算token 维模块统一引入 valid_rows（1～64）
二重复 cache clean 可能是板级耗时异常的重要来源权重只 clean 一次；cache 所有权集中到 M03，wrapper 不再自行清理整块 buffer
三不能先简单增加大量并行单元约 97.4% CLB、83.5% BRAM、22.7% DSP；瓶颈是布局空间、BRAM 与布线，Attention/SwiGLU 必须先改 tile 结构
四实际不是所有 IP 都挤在 HP3HP0～HP3 已分组使用，第一版保持；只有 AXI 计数器证明拥堵后才重新分配
五PS HP 的 128 bit 是 PS IP 配置决定的扩大 HLS 端口可改善 burst 与内部并行，但不能把 PS DDR 物理出口变成 512 bit
六必须先冻结可追溯版本任何优化前记录源码 commit/dirty patch 与 bit、XSA、ELF、component.xml、权重的 SHA-256
关于结论三的数据口径：97.4% CLB / 83.5% BRAM / 22.7% DSP 是整个 rmsnorm_axu9egkv_gqa_lmhead 工程的占用，不是 lm_head_argmax 单个 IP 的占用 —— 模块 16 单独综合只用了 14 个 BRAM18K、5 个 DSP、5,816 LUT。
