研究11：部分通道预筛

读取hidden与列RMS选择d个通道遍历全词表计算d维预览按history执行penalty并稳定Top-T并入特殊ID，完整896维BF16精算
参数
dynamic：d=16/32/64/128，T=1024/4096/16384；static：d=32/128，T=4096/16384。dynamic按|h_j|×RMS(W[:,j])选通道；static按列RMS选固定通道。
来源与拟合
RMS仅由canonical W构造，不训练LM或读取校准标签。预览用所选通道顺序的相邻FP32树；其近似算术与原896维精算分别记录。
乘法与访存模型
selector ≈ V×d + [dynamic时H]；exact = K×H。预览BF16逻辑读取2Vd，精算2KH。Top-T排序输入仍是V。
本轮结果
非全词表端点中，各类校准≥99%有6个，≥99.9%有4个。各类校准≥99%中GPU最快，仅描述性观察：partial_dynamic_d128_T1024，整体召回99.97906%，漏1/4775，GPU 129.58次/s；最低类别99.91489%。
该点逻辑预算
20.38M乘法项；主逻辑读取38.87MiB；权重＋索引最低预算519.32MiB（未含共同缓冲）。
FPGA适配
动态方案需要列方向访问；保留行式W用于精算时，完整列式副本使两份W达到519.31MiB，已超旧320MiB arena。静态d128可只存37.09MiB预览列，d32为9.27MiB。权重预算只是下界，仍要加共同缓冲、输出、guard和对齐。
实现约束
可以按1024词一块存储[tile,channel,token]：块内分数只需4KiB，选择的d列按连续小突发读取，避免把全V分数都放BRAM。但跨通道归约顺序、动态地址、Top-T稳定同分规则和双布局loader都要另开发/验证。没有因此取得HLS或200MHz资格。

研究12：全词表权重亲和倒排桶

归一化原训练hidden中心按W与中心亲和度为每词分配P个桶查询h与C个原型的分数选R桶、合并完整ID列表完整BF16候选精算
参数
C=128/256，P=1/2，R=4/8/16/32；另C128/256、P1、R=C两个全词表端点。所有桶完整保存，不使用旧L上限截断。
来源与拟合
中心只来自原训练资产；token归桶使用完整canonical W，按亲和分数稳定取top-P。没有用校准标签选桶或拟合，所有151936词至少进入一个桶。
乘法与访存模型
selector = C×H；exact = K×H；ID读取 = 4E，其中E为所选桶条目总数，可能因P>1而大于最终K。
本轮结果
非全词表端点中，各类校准≥99%有0个，≥99.9%有0个。未找到各类校准≥99%的稀疏点；展示最高整体召回点：affinity_C128_P2_R32，整体召回93.44503%，漏313/4775，GPU 114.59次/s；最低类别84.08511%。

37.35M乘法项；主逻辑读取71.45MiB；权重＋索引最低预算261.03MiB（未含共同缓冲）。
FPGA适配
中心与查询点积很小，完整倒排ID索引只需4PV字节加偏移；桶内ID已按全局ID递增，有利于候选行读取。完整支持集解决了旧列表约9.9万词的来源上限，但小R是否命中仍完全由实测决定。
实现约束

研究14：角度／内积变换多表哈希

固定BF16随机超平面构建每表完整倒排索引h投影得到hash码读取相同桶或Hamming1邻桶并集去重，完整BF16精算
参数
angular/mips × b=8/10 × active tables=4/8 × Hamming radius=0/1；seed=20261024。当前GPU原型统一算8表投影，即使只探测4表，乘法项仍按8bH统计。
来源与拟合
angular直接按随机投影符号建桶；mips令M=max||w||，使用[w/M,sqrt(1−||w||²/M²)]和[h,0]的球面变换；查询正比例归一化不改变符号。完整W建索引，不使用训练/校准赢家标签。并非ALSH2014完整复现或有已验证的次线性速度保证。
乘法与访存模型
当前selector = 8×b×H；radius1读取桶数L×(b+1)，radius0为L。exact = K×H；ID读取4E；存8表ID为32V字节，另偏移和8b×H BF16投影。
本轮结果
非全词表端点中，各类校准≥99%有0个，≥99.9%有0个。未找到各类校准≥99%的稀疏点；展示最高整体召回点：lsh_angular_b8_L8_p1，整体召回45.82199%，漏2587/4775，GPU 109.51次/s；最低类别42.55319%。
该点逻辑预算
34.54M乘法项；主逻辑读取66.05MiB；权重＋索引最低预算264.41MiB（未含共同缓冲）。
FPGA适配
投影乘法很少，随机offset查询与连续桶列表可分开流水；然而桶长偏斜、邻桶探测放大、去重与最终K可能主导。构建观察最大桶约5.9万–6.5万词，必须按真实长度处理，不能靠平均V/2^b估算缓冲。
实现约束
当前GPU variable gather会按本次最大桶长构造padding索引；FPGA可改为按counts逐桶流式，但需要另实现。MIPS球面增强受最大权重范数和投影偏斜影响，不能预设它一定优于角度哈希。原型没有用隐含dense fallback抬高召回。

计算量与FPGA适配：怎样理解表中的预算

H=896，V=151936，K为每步真实去重候选数，E为实际所读ID条目数（包含重复）。dense每步V×H=136,134,656个乘法项，BF16权重259.65625MiB。乘法项是算法产品数，不等于DSP数量或时钟周期；加法树、policy、排序和位图操作另计。

原方案乘法项主要逻辑读取
仅聚类CH＋KH2CH＋4E＋2KH
仅低秩r(H＋V)＋KH2r(H＋V)＋2KH
原融合CH＋r(H＋V)＋KH2CH＋2r(H＋V)＋4E＋2KH

三个不能混用的量

① 表中的读取量是假定指定布局下的逻辑字节，不含burst浪费、cache、history、分数/排序缓冲和AXI控制，未测实际AXI。② 存储预算是完整W加索引/预览副本的下界；低于320MiB不代表布局已通过，高于则已经需要新arena。③ 分阶段测量加入了同步屏障，是单独instrumented run；其阶段和不能替代主图中120次完整调用的实测速率。

片上存储和流水线的具体约束

  • 全词表候选位图18,992B，理想纯容量约9个BRAM18K；同字OR并发需要转发/合并，不能丢更新。实际资源还由端口、bank和综合决定。
  • 全V FP32预览分数607,744B，若全部放片上，理想纯容量约264个BRAM18K；按1024词分块只需4KiB局部分数，但仍要完成全局Top-T。
  • 只存候选ID与FP32分数需约8T字节：T1024为8KiB，T4096为32KiB，T16384为128KiB，尚未计入排序工作区。
  • 静态通道可打包固定列；动态通道需要支持任意选列，采用分块列式副本可节省每步读取但增加约259.66MiB常驻权重。原行式精算权重仍需保留。
  • 候选全局排序后，896维精算可按一行一行读取；桶/哈希的列表和offset流量、重复去重开销必须另计。GPU padding gather成本不能直接等同于FPGA的流式counts循环。
  • 新预览树、动态地址、bias、Top-T、descriptor/版本身份、PS加载布局必须重新冻结。原v3.1/v4组件可作为父版本参考，不能继承新系统200MHz或实板资格。

T≥max(主逻辑字节/B有效带宽，乘法项/(P并行乘法槽×f时钟)) 只是在指定布局和理想流水线下的乐观下界；B、P未实测，排序/调度等亦未计入，因此本报告不给出“FPGA预计快几倍”的数值。
