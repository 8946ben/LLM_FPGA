5. HLS 模块设计（模块 16）

本章介绍模块 16（LM Head）的 Vitis HLS 实现，对应目录 module16_lm_head_hls/。模块 16 是推理链的最后一环：把 896 维 hidden 向量与 151936×896 的权重矩阵相乘得到词表 logits，再施加 repetition penalty，最后 argmax 选出下一个 token。

RMSNorm 不在本模块内，本模块只做「线性层 + penalty + argmax」三件事。另外 Qwen2.5-0.5B 的 lm_head 与 embed_tokens 共享权重（tied weights），权重文件即 artifacts/model.embed_tokens.weight.fp16.npy，约 260MB。

顶层函数与接口

内核以 extern "C" 导出，4 个内存指针各自映射到一路独立的 m_axi bundle，互不抢带宽：

参数m_axi bundledepth备注
hiddengmem_hidden896输入 hidden 向量（FP16）
weightgmem_weight136134656 = 151936×896 个 half带 max_read_burst_length=256、num_read_outstanding=16
history_bitmapgmem_history4748 个 u32 word已生成 token 的位图
raw_logitsgmem_logits151936输出词表 logits（FP16）

所有指针地址、标量参数以及 return 统一挂在 s_axilite bundle=control 上，由 PS 端通过寄存器读写控制。

数据类型与计算路径

  • 输入 hidden、权重、输出 logits 均为 FP16（hls_half.h 的 half），没有整数量化。
  • 矩阵乘：FP16×FP16 乘法，FP32 累加（float accumulator），最终结果再转回 FP16 写出。
  • repetition penalty 在 FP32 域进行：logit 为负数则乘 penalty，为正数则除 penalty。
  • argmax 在 FP16 域进行；相同分数时保留较小的 token ID。
  • history bitmap 为 ap_uint<32> 数组，每个 token 占 1 bit，共 (151936+31)/32 = 4748 words，用于标记哪些 token 需要施加 penalty。

关键 pragma

#pragma HLS BIND_STORAGE variable=hidden_cache type=ram_1p impl=bram
// load_hidden 循环：PIPELINE II=1
// LOOP_TRIPCOUNT min=1 / max=896（hidden 维度）
// LOOP_TRIPCOUNT max=151936（词表维度）
性能瓶颈：内层 dot_product 循环没有显式 pipeline pragma，综合后自动流水仅达到 II=8（FP32 累加的依赖链所致），这是当前的主要性能瓶颈。

Testbench 设计

tb/lm_head_tb.cpp 包含两类测试：

  • run_synthetic_test()：4×4 手工构造用例。token0 的 raw 分最高但受 penalty 压制，正确结果应选 token1 —— 用来验证 penalty 真正改变了 Top-1，而不只是走个过场。
  • run_trace_case()：加载真实 fixture（hidden.fp16.bin / golden_logits.fp16.bin / history_bitmap.u32.bin / expected_token.txt）。判定标准：token 匹配 + max_abs_error ≤ 0.02 + cosine ≥ 0.999 + Top-5 重合 ≥ 4。

testbench 自带 NPY v1/v2/v3 的 FP16 解析器，可直接读取 .npy 权重。运行模式：

命令行行为
无参数仅运行 synthetic 测试
--trace-all weight.npy fixture_root一次加载权重，连续跑 8 步 trace
--trace ...单步 trace

仿真流程

脚本作用要点
run_csim.tclC 仿真vitis_hls -f run_csim.tcl；默认 --trace-all 跑全 8 步，-tclargs N 跑单步；part xczu9eg-ffvb1156-2-i，5ns 时钟

验证结论

  • 全尺寸 C 仿真 8/8 trace 通过：max err ≤ 0.0156、cosine = 1.0、Top-5 全中。
  • cosim 4×4 同构核 PASS（XSim 1/1）。
  • TCP 回环 8/8 通过（见第 6 章协议层）。

当前版本定位为 correctness baseline：功能全对，但尚未做多 PE / 分 bank 并行优化。后续计划：

  1. 多 PE 点积，消除 II=8 瓶颈；
  2. PS DDR4 / AXI HP 数据通路；
  3. bitstream 板级验证 —— 已在 realFpga/ 完成，见第 7 章。
