8. 工具链与测试

前面几章分别讲了模型、golden trace、Python 参考实现、HLS 内核和板卡部署。本章介绍把这些环节串起来的工具链：tools/ 目录下的 8 个脚本、tests/ 目录下的单元测试，以及 artifacts/ 目录下的各类产物。理解这些工具，就理解了整个工程「数据是怎么流动的、正确性是怎么被验证的」。

所有脚本都假设在仓库根目录 D:/program/LLM_FPGA 下运行，路径均使用相对路径。

tools/ 脚本一览

tools/ 目录共 8 个 Python 脚本，按用途可以分为四组：权重与模型查看、fixture 生成、板端测试、辅助工具。

脚本作用
export_lm_head_weight.py 纯 Python + NumPy（不依赖 torch）从 safetensors 抽取 model.embed_tokens.weight [151936, 896]（即 tied lm_head 权重），支持 BF16 移位转 FP32，默认导出 FP16 .npy。产物为 artifacts/model.embed_tokens.weight.fp16.npy，约 260MB。
inspect_qwen_model.py 只读 config.json 和 safetensors header，打印架构参数、逻辑模块结构、各权重 tensor 的名称 / shape / dtype 及第 0 层权重清单（FPGA bring-up 指南）。支持 --filter "model.layers.0" 过滤、--max-weights 限制输出数量。
orin_qwen25_smoke.py Jetson Orin 上的冒烟测试：FP16 eager 加载模型跑 greedy 生成，打印加载时间、tokens/s 和回复文本。
prepare_lm_head_hls_fixture.py 从 trace 目录生成紧凑的 HLS testbench fixture（artifacts/module16_hls_fixtures/step_NN/）：hidden.fp16.bin（896 维最后位置 hidden）、golden_logits.fp16.bin（151936 个 raw logits）、history_bitmap.u32.bin（4748 字已出现 token 位图）、expected_token.txt，外加顶层 manifest.json。
read_npy.py 通用 .npy 查看器：支持单文件或目录扫描，打印 shape / dtype / min / max / mean / std 及前 N 个采样值。
run_module16_board_trace.py 核心 host 程序：通过 LMH1 TCP 把一步 fixture 送到真实 AXU9EGB 板（默认 192.168.8.190:19016）或本地 NumPy 仿真器。支持 --load-weight（1MiB 分块上传）、--vocab-limit 渐进式验证、--return-logits 回读比对（raw atol 0.02）、可选 repetition penalty 复现 model.generate 的 processed scores；输出 MODULE16_TRACE ... status=PASS/FAIL。
run_module16_tcp_loopback.py 本机 TCP loopback 冒烟：NumPy 仿真器 + 真实 fixture 跑一步，校验 ping(896/151936)、token、max_abs ≤ 0.02、top5 重叠 ≥ 4。
stage_h4_board_small_test.py 真板上手算可验的 4×4 小测试：上传 4×4 FP16 权重，验证 ping、repetition penalty 改变 top1、argmax tie 保留小 id、token-only 响应、维度不匹配报错后同连接恢复。

权重导出：export_lm_head_weight.py

Qwen2.5-0.5B 的 lm_head 与 embedding 共享同一份权重（tied weights），因此 safetensors 里只有 model.embed_tokens.weight。这个脚本不依赖 PyTorch，直接解析 safetensors 格式把这份 [151936, 896] 的权重抽出来：源权重是 BF16，脚本通过移位转成 FP32，再默认导出为 FP16 的 .npy 文件，供 HLS 仿真和板端上传使用。

模型查看：inspect_qwen_model.py

bring-up 阶段经常需要确认「某个 tensor 叫什么、shape 是多少、dtype 是什么」。这个脚本只读取 config.json 和 safetensors 的 header（不加载权重数据），因此启动极快，适合当作随手翻的「模型结构字典」。

fixture 生成：prepare_lm_head_hls_fixture.py

golden trace 目录里的中间量是全量的，直接喂给 HLS testbench 太大。这个脚本把每一步 decode 需要的最小输入集压缩成 4 个文件，加上顶层 manifest.json 索引，构成一个自包含的测试夹具（fixture）。

板端验证三件套

板端验证按「从小到大」分三层：

  1. 4×4 小测试（stage_h4_board_small_test.py）：权重小到能手算，专门验证协议与边界行为（tie、penalty、错误恢复）。
  2. 本机回环（run_module16_tcp_loopback.py）：不碰真板，用 NumPy 仿真器验证 host 端协议栈和 fixture 本身。
  3. 真板 trace（run_module16_board_trace.py）：把完整 fixture 通过 LMH1 TCP 送到 AXU9EGB，逐步比对输出 token 与回读 logits。

tests/ 单元测试

tests/ 目录使用 Python 标准库 unittest 框架，不需要额外安装 pytest。运行方式：

# 运行单个测试文件（二选一）
python -m unittest tests.test_lm_head_cpu_reference
python tests/test_lm_head_cpu_reference.py
测试文件覆盖内容
test_lm_head_cpu_reference.py 测 last_hidden_state 取尾、分块 matmul 与 dense FP32 一致、repetition penalty 去重、argmax tie 取最小 id、FP16 cast 后 tie 行为、内建 safetensors 读取器的 BF16 解码。
test_module16_tcp_protocol.py 测 LMH1 协议帧 round-trip、CRC32 错误拒绝、socketpair 上的权重上传 + ping + penalty argmax、tie 保留最小 token id。
这些单测锁定的是「容易被改坏」的语义细节：例如 argmax 出现并列最大值时必须取最小 token id、FP16 量化可能制造新的 tie、CRC32 错误的帧必须被拒绝。修改 Python 参考实现或协议代码后务必重跑。

artifacts/ 产物

artifacts/ 目录存放权重副本与各类导出产物，是工具链的「原料仓库」：

产物说明
Qwen2.5-0.5B-Instruct/model.safetensors 约 988MB 的本地权重副本，SHA-256 fdf756fa... 与官方一致。
model.embed_tokens.weight.fp16.npy 约 260MB 的 FP16 lm_head / embedding 权重，供 HLS 仿真与板端上传。
module16_cpu_logits/00..07_computed_logits_fp32.npy 每步 151936 维 FP32 CPU 计算 logits。
module16_hls_fixtures/ manifest.json + step_00..07 各 4 文件的紧凑 fixture。

数据流闭环

把上面的脚本串起来，就构成模块 16 的完整验证数据流：

run_full_generate_trace.py（插桩 FP16 推理）
        │  导出 golden trace
        ▼
qwen25_0p5b_instruct_full_generation_trace/
        │  prepare_lm_head_hls_fixture.py 压缩成 fixture
        ▼
artifacts/module16_hls_fixtures/
        │  run_module16_board_trace.py 经 LMH1 TCP 送出
        ▼
HLS IP / 真实 AXU9EGB 板卡
        │  回读 token 与 logits
        ▼
与 fixture golden + processed scores 双重比对
「双重比对」指既比对 raw logits（FP16 精度门限 atol 0.02），也比对经过 repetition penalty 处理后的 processed scores（复现 model.generate 的行为），确保板端实现的语义与 PyTorch 完全一致。

常用命令速查

# 查看模型结构（打印架构参数与前 80 个权重）
python tools/inspect_qwen_model.py artifacts/Qwen2.5-0.5B-Instruct --max-weights 80

# 只看第 0 层的权重
python tools/inspect_qwen_model.py artifacts/Qwen2.5-0.5B-Instruct --filter "model.layers.0"

# 查看一个 .npy 文件的统计信息
python tools/read_npy.py <路径>

# 运行全部单元测试
python -m unittest discover tests

# 本机 TCP 回环冒烟（不需要真板）
python tools/run_module16_tcp_loopback.py
