阶段分解（ms，线性同尺度）

v4 的 radix 阶段（7.80 ms，43% 时长）完全不占 DDR 读通道；预览 + 精算合计读忙碌仅 8.40 ms / 18.21 ms ≈ 46%。这两点是步间流水化与双 master 并发的直接优化空间（见下）。

v4 参数敏感性（解析模型，实时重算）

模型：预览拍 = 149×d×128，预览周期按 r3 实测比例 93.0% 拍占用折算；K = T + 13（特殊 ID；d64/T4096 该 fixture 实测并列≈0，其余 T 未验证并列数），精算 dataflow 按 653,494 × K/4109 线性缩放 + 固定预取/policy 43,524 拍；radix 扫描量与 d/T 无关（全 151,936 key），保持 1,560,505 拍。质量结论与周期估计相互独立：换 d/T 必须重新做质量验证。

优化要点（由上面数字直接推出）

v4（当前方向）

  • 步间流水（收益最大）：radix 7.80 ms 期间 DDR 读通道空闲，且与 d/T 无关。给 key 缓存做双缓冲后，第 N 步的 radix 可与第 N+1 步的预览并发，单步周期理想降至 3,642,879 − 1,560,505 ≈ 2.08 M 拍 ≈ 10.41 ms（对 v3 约 11.3×）。
  • 双 master 并发预览：meta master 在预览期闲置。两 master 各读一半 tile，预览 6.56 ms → ~3.3 ms，单步约 15.0 ms。
  • radix II 2 → 1：每 key II=2（303,872 拍/趟），II=1 可省约 0.6 M 拍（~3 ms），但需解决 banked BRAM 读写冲突。
  • 精算行分散：4,109 行 × 1,792 B 随机地址破坏 DDR 行缓冲；候选 ID 排序后顺序发出 + 更深 outstanding 可把读拍占用从 66% 推向 ~93%（精算 3.49 ms → ~2.5 ms）。点积当前 128 拍/行（7 MAC/拍），加宽乘法前先解决读效率，否则读成为新瓶颈。
  • 提频：HLS 时序估计 3.650 ns（274 MHz），若实现达成再 ×1.37；与上述手段正交。

v3（dense 基线）

  • 纯带宽下限：W = 17,016,832 拍 = 85.08 ms（128 bit @200 MHz 连续流）。实测 117.75 ms → 拍占用 72.3%，加深 AXI outstanding / 行预取的理论上限约 1.38×。
  • 计算不是瓶颈：5.78 MAC/拍（DSP 59），加宽乘法器不改变时延；dense 的根治手段只有减字节 —— 即 v4 路线（本例字节 9.9%、周期 15.5%）。
  • 200 MHz 实现已收敛（WNS +0.943 ns）；提频受 AXI/SmartConnect 与 PS DDR 时序约束，v3.1 迁 PL DDR 后 IP 耗时持平（117.75 ms），说明瓶颈在结构而非 DDR 位置。

相关但不可直接比较的数字

压力 AXI 模型：full_r3 联合 CoSim 对 AR/R/AW/W/B 每次回调注入 0~256 拍随机延迟。该抽象模型下仅读通道传输+间隔期望 ≈ 366.98 ms —— 这说明真实 DDR 延迟/停顿对 v4 这种多 burst 结构影响巨大（预览 9,536 个 2 KiB 列读 + 精算 4,109 个行 burst），不是正常 decode 时序，但提示 outstanding 深度与 burst 合并是 RTL 优化重点。
