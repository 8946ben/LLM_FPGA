THE SHARED PROBLEM

每生成一个词，为什么要读这么多权重？

模型最后得到一个 hidden 向量 h。输出头 W 的每一行对应一个 token；对每行做点积，就得到该词的原始分数。全词表 dense 要对 151,936 行分别计算 896 维点积。

sᵢ = wᵢᵀh = Σⱼ Wᵢⱼ hⱼ winner = argmaxᵢ policy(sᵢ, history) 本项目 policy 对 history 中已出现的词施加 1.1 倍重复惩罚：负分乘 1.1，非负分除 1.1；稳定同分选择较小 ID。

这里的稀疏化围绕“哪些词需要完整点积”展开。先用便宜的规则构造候选集 S，再只读取候选对应的原始 BF16 权重行，按固定 FP32 运算合同精算。权重本身仍然保留。

00 / REFERENCE

Dense：完整词表逐行精算

对照基线

把每个词都算一遍，作为其他方案的比较对象。

直接计算 Wh，再对全部词执行 history policy 和稳定最大值选择。没有候选召回损失；相对它自己的赢家定义，覆盖率为 100%。

每步乘法项 = VH = 151936 × 896 = 136,134,656 BF16 权重大小 = 2VH = 259.65625 MiB

它的优点是流程规则、权重行连续；代价是每步都涉及整个大矩阵。稀疏方法需要在候选生成开销与减少的精算工作之间取得收益。

01 / CLUSTER · 实验 1、8

L2 投票聚类：相似的 hidden，复用相似的候选表

训练统计路由

先问“当前状态像哪一类训练状态”，再查那一类常见的高分词。

离线：聚类 hidden训练 h 做 L2 k-means，得到 C 个中心
→
离线：投票建表按簇累积高分词与赢家票数
→
在线：最近 R 簇取各表前 L 个词，合并后精算

项目聚类的对象是训练 hidden 向量。每簇候选表的词，由这个簇里的训练样本投票产生：raw Top 词按排名获得 1/rank 票，dense 赢家额外获得 4 票。票数降序，同票按 ID 排序。

D꜀(h) = ‖h − μ꜀‖² = ‖h‖² + ‖μ꜀‖² − 2 μ꜀ᵀh S = ⋃꜀∈最近R簇 List꜀[:L] ∪ Special

参数怎样影响它？

C128_R4_L16384 表示 128 个中心、选最近 4 簇、每簇最多读 16,384 个有效 ID。实际 K 是去重结果，通常小于 R×L+14。C 增大会细分空间，但每簇训练样本也可能减少；增加 R 或 L 通常扩大候选。

为什么会漏？

新状态可能落到错误簇；赢家可能没在该簇的训练投票中出现，或被列表上限截掉。即使读全部簇，训练列表也不保证覆盖整个词表。旧路由遇到空簇使用显式 dense fallback，这种回退应单独统计。

主要乘法项约 CH＋KH；优点是不需要每步扫描所有词的预览权重。列表覆盖依赖训练分布。

02 / LOW RANK · 实验 1、9

低秩预筛：用少量共同方向，估计所有词的分数

子空间近似

让每个词先在 r 维空间里便宜地比一次，只给领先者完整精算。

离线对 W 的列空间提取主要方向。项目通过 WᵀW 的特征分解构造按能量排序的基 B ∈ ℝᴴˣʳ，并计算 A = WB ∈ ℝⱽˣʳ。理想实数下，W ≈ ABᵀ；项目将因子存为 BF16，因此还包含因子量化误差。

r 与 T 是两个不同旋钮

r 越大，保留的子空间越多，预览一般更接近原分数，但每步全词表预览更贵。T 越大，保留的近似领先词越多，漏选通常减少，精算代价增加。例如 r64_T16384 是 64 维预览后保留 16,384 个词。

为什么会漏？

被舍弃方向可能恰好决定两个高分词的次序；整体矩阵重构误差小，并不保证赢家排序正确。只要真实赢家的预览排到 T 之后，就无法被该路找回。

乘法项约 r(H＋V)＋KH。低秩仍扫描整个词表，只是每行由 H 维减为 r 维。即使 r=H，BF16 因子与运算顺序也不自动等同原数值合同；T=V 则从候选覆盖上回到全词表。

03 / HYBRID · 实验 1、10

聚类＋低秩融合：用候选并集互相补漏

双路召回

聚类靠训练经验，低秩看当前分数；任一路找到词，就保留它。

两路独立生成候选，再按全局 ID 合并、排序和去重，最后统一用原权重精算。这里的“融合”是集合并集，不是把聚类分数与低秩分数做加权平均。

S = Scluster ∪ Slowrank ∪ Special 最终漏选 = 聚类漏选 ∩ 低秩漏选

例如本项目两套方法分别为 C128/R4/L16384 + r128/T16384 和 C256/R4/L8192 + r64/T16384。低秩可以补回训练列表未收录的词，聚类也可以补回低秩排序落后的词。质量收益取决于两路的错误是否互补；不能直接把两个漏选率相乘。

04 / PARTIAL CHANNEL · 研究 11

部分通道预筛：只看当前最重要的几列

原始坐标子集

896 个通道不必先全部读出；先用其中 d 个通道估计哪些词值得精算。

它直接保留 W 的部分原始列。静态方案总用列 RMS 最大的 d 列；动态方案结合当前 hidden，按 |hⱼ| × RMS(W[:,j]) 排序，每步选择不同的列。RMS 是整个词表上该列权重的均方根。

RMSⱼ = √(Σᵢ Wᵢⱼ² / V) Jdynamic = Top-dⱼ(|hⱼ| × RMSⱼ)　　Jstatic = Top-dⱼ(RMSⱼ) ŝᵢ = Σⱼ∈J Wᵢⱼ hⱼ S = TopT(policy(ŝ, history)) ∪ Special
选 d 个原始通道不做低秩旋转
→
全词表 d 维预览读对应 d 列
→
Top-T 与精算候选恢复完整 H 维

与低秩有什么区别？

低秩的每个方向通常混合所有原始通道；部分通道只选坐标子集。前者读低秩因子，后者读 W 的原始列。动态选列可以随 h 改变，不需要用赢家标签训练。

误差与实现代价

被忽略通道的总贡献可能很大，也可能与已选通道抵消；列 RMS 是全词表统计，不能保证对某个赢家最优。动态列访问还需要合适的列式或分块权重布局；保留行式精算权重时可能要增加副本。

主要乘法项 Vd＋KH，另有动态 H 维打分及选择。Top-T 的输入仍有 V 个词。下方可以实际调节 d 和 T，观察赢家漏选。

05 / AFFINITY BUCKET · 研究 12

全词表倒排桶：先把每一个词都放进索引

权重亲和归桶

为整个词表建立可查询的目录，在线只打开分数最高的几个目录。

项目沿用训练 hidden 的中心并归一化为原型 p。离线计算每个词权重 wᵢ 与所有原型的亲和分数，将词放入得分最高的 P 个桶。每个桶保存完整的 ID 列表，不使用旧聚类的 L 截断。

Assign(i) = TopP꜀(wᵢᵀp꜀) Bucket꜀ = {i | c ∈ Assign(i)} 在线 q꜀ = p꜀ᵀh；S = ⋃꜀∈TopR(q) Bucket꜀ ∪ Special

与投票聚类最关键的差别

投票聚类记录“训练状态中哪些词曾得高分”；这里根据完整 W 给每个词分配桶，因此词表覆盖完整。P=2 时，每词进入两个桶，索引有 2V 个 ID 条目。

全覆盖为什么仍会漏？

每词有桶，只说明它能被某次查询取到。当前 h 选中的 R 个桶仍可能不含赢家；桶原型得分不能准确代表桶里每个词。增加 P 或 R 会扩大支持和流量。R=C 时覆盖全部词，成为完整性对照端点。

乘法项约 CH＋KH。每词索引占 4P 字节，另有偏移表；所读条目 E 可含重复，去重后的候选数为 K。桶长不均会影响缓冲与耗时。

06 / LEARNED ROUTER · 研究 13

学习式桶路由：直接学习“哪个桶可能装着赢家”

监督线性筛选器

桶保持不变，把选桶规则换成用训练样本拟合的预测器。

它与倒排桶共用完整的词—桶分配。离线将训练样本的 dense 赢家映射到所属桶，并加入 raw Top256 词的软标签：赢家标签总权重为 1，按 1/rank 归一化的 Top256 标签总权重为 0.25；词在多个桶时均分权重。

训练：min Θ,b mean ‖y − (Θx + b)‖² + λ‖Θ‖²，λ = 0.01 在线：q = Gh + b S = ⋃꜀∈TopR(q) Bucket꜀ ∪ Special

项目采用 ridge 线性回归。训练输入按通道中心化、标准化，完成后将变换折叠进系数；在线仅使用 BF16 的 G[C,H] 与 FP32 bias。原 LM 和原始输出权重 W 均不因此训练。它受 Learning to Screen 思路启发，是本项目的线性桶原型。

它学到的是什么？

亲和桶直接使用原型点积；学习路由会调整每个通道对桶分数的作用，使训练中含赢家的桶更靠前。分数只是选桶信号，不是最终词概率，最后仍需精算。

为什么监督也不保证命中？

线性能力有限，训练分布可能不能代表新状态。标签中的 dense 赢家受 history 影响，而当前路由仅输入 h；相同 h、不同 history 可能需要不同桶，筛选器无法直接区分。

乘法项约 CH＋KH，另有 C 次偏置加法。在线筛选器小，不代表 K 小；训练效果应在独立数据上检验。

07 / MULTI-TABLE LSH · 研究 14

多表哈希检索：相似方向，争取落进相同的桶

随机投影索引

把高维向量压成一小串二进制码，用查表替代逐词评分。

每张表选 b 个固定随机超平面。向量在每个超平面的哪一侧决定一个 bit，b 个符号拼成桶号。离线将全部词权重写入每张表的倒排桶；在线对 h 算哈希码，取同码桶，必要时再探测汉明距离为 1 的邻桶，跨表合并后精算。

bitⱼ(x) = 1[rⱼᵀx ≥ 0]；code(x) = Σⱼ bitⱼ(x)·2ʲ 半径 0：每表查 1 个桶 半径 1：每表查自身＋翻转任一 bit 的 b 个邻桶，共 b＋1 个桶

页面里的两个变体

Angular：直接比较方向

对 w 和 h 直接做随机符号投影。方向越接近，碰撞概率越高。但目标是最大内积；一个范数大的权重即使夹角稍大，也可能得到更高点积，方向相似不能完整反映内积排名。

MIPS：把内积改写为球面相似

令 M 为最大权重范数，构造 w′=[w/M, √(1−‖w‖²/M²)]，查询用 h′=[h,0]。所有 w′ 的范数为 1，点积为原内积除以 M；固定非零 h 时，角度排序因此对应原内积排序。

w′ᵀh′ = wᵀh / M；‖w′‖ = 1 示例：angular_b8_L8_p1 = 8 bit / 表，查 8 张表，邻桶半径 1

变换建立的是理想相似度关系；有限随机位数、表数与探测预算仍可能错过赢家。MIPS 哈希也没有直接建模 history 惩罚。表越多、邻桶越多通常召回更高，但读到的条目和去重开销也增加；b 越大，桶通常更细，命中更难。

当前项目原型固定计算 8 张表的投影，即使只探测 4 张表，投影乘法项仍为 8bH。哈希并非必然次线性：大桶、偏斜和精算 K 都可能主导时间。这里的 L 指表数，与聚类每簇上限 L 含义不同。
