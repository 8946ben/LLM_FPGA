## 2. 项目背景速览

**工程目标**：Qwen2.5-0.5B-Instruct 的 FPGA 推理验证，路线是 correctness-first —— 先用 PyTorch 导出逐模块 golden 张量，再用 HLS 实现同一模块并逐项对拍，最后在真实板卡上跑通完整 trace。当前目标是建立可信、可重复的正确性基线，不是生产推理服务。

| 项 | 值 |
| --- | --- |
| 模型 | `Qwen/Qwen2.5-0.5B-Instruct`（24 层 / hidden 896 / GQA 14:2 / vocab 151936 / BF16 / tied embedding） |
| 板卡 | ALINX AXU9EGB，`XCZU9EG-2FFVB1156I`（Vivado part `xczu9eg-ffvb1156-2-i`） |
| 工具链 | Vivado / Vitis HLS / Vitis 2021.1 |
| 板卡地址 | `192.168.8.190`，上位机 `192.168.8.12/24`，LMH1 服务端口 `19016` |
| 当前移交模块 | 模块 16 = `lm_head_argmax`（LM Head + repetition penalty + argmax） |

**模块 16 已通过的验证（结论未变，仅收录）**：

```text
CPU 真实权重矩阵乘      8/8 token 一致，cosine 1.000000000，最大绝对误差 ≤ 0.0078125
全尺寸 HLS C 仿真       8/8 PASS，Top-5 5/5，HLS_CSIM_OVERALL=PASS
ZU9EG 综合              估计 3.650 ns（≈273.97 MHz），5.489 s/token
RTL co-simulation       1/1 事务，542 cycles，XSim PASS
TCP 端到端回环          8/8 PASS，最大绝对误差 ≤ 0.0078125
真实板卡 8-step         token 8/8、raw logits 8/8、processed scores 8/8、Top-5 每步 5/5
```

**当前性能基线**：板上实测约 **11.09 s/token**（串行单累加器，点积 II=8）。性能优化尚未开始，见 §4.6。

### 3.2 画布化：图可缩放平移

**问题**：Mermaid 默认 `useMaxWidth: true`，会把 SVG 整体缩放到容器宽度。首页图自然宽度约 2400px、容器约 1100px，节点文字被压到约 40%，无法阅读。

**解决**：`assets/wiki-init.js` 做了两件事 ——

1. 所有 Mermaid 图表类型改 `useMaxWidth: false`，SVG 按 `viewBox` 自然尺寸渲染
2. 渲染完成后把每张图包成画布，结构为 `figure > toolbar + canvas-viewport > canvas-stage > svg`

**交互清单**：

| 操作 | 方式 |
| --- | --- |
| 缩放 | 滚轮（以指针为锚点）、`+`/`−` 按钮、键盘 `+` `-` |
| 平移 | 拖拽、方向键、触屏滑动 |
| 视图 | `适应宽度`、`适应窗口`、`1:1`、双击复位、键盘 `0` |
| 范围 | 15% ~ 800%，工具栏实时显示百分比 |

**两个关键实现细节，改动前务必理解**：

1. **初始视图为 1:1**，不是适应宽度 —— 这是刻意的，保证字号清晰；用户可一键切到适应宽度。
2. **拖拽位移超过 6px 时会抑制随后那次 click**。首页图有可点击节点，没有这个抑制就会出现「拖一下图就跳到别的页面」。

## 6. 环境与常用命令

### 6.1 浏览 wiki

直接双击 `doc/wiki/index.html`。无需 dev server、无需联网。

### 6.2 验证 wiki 的图（改动图之后建议跑一遍）

思路是用 jsdom 加载本地 `mermaid.min.js`，对每张图调用 `mermaid.parse()`。关键点：

- `mermaid` 在 Node 下要用 `require()`（UMD 的 CommonJS 分支），`dom.window.eval()` 那条路不一定能拿到实例
- 从 HTML 中提取 `<div class="mermaid">…</div>` 后，必须先把 `&lt;` `&gt;` `&quot;` `&amp;` 解码回原字符，否则解析会失败
- 构造 jsdom 时 XML 模式必须给根元素：`new JSDOM('<root/>', { contentType: 'text/xml' })`

```powershell
npm install jsdom          # 在临时目录安装即可，不要装进仓库
node <你的检查脚本>.js
```

### 6.3 验证画布逻辑

`window.WikiCanvas` 已暴露 `{ attachAll, createCanvas }`，可直接在 jsdom 里手动调用 `createCanvas(figure)` 做断言，无需真实渲染。

## 7. 已知限制与坑

### 7.1 本机无法用浏览器截图核对

`playwright-cli` 启动 Chrome 时报 `spawn UNKNOWN`，是环境沙箱限制，装浏览器也没用。**因此 wiki 的所有验证都停留在 jsdom 的逻辑层与配置层，没有做过像素级复核**。接收人第一次接手时请务必人工打开页面确认渲染效果。

### 7.2 Mermaid 的 `useMaxWidth` 是字体变小的根因

任何新增 Mermaid 图都必须保持 `useMaxWidth: false`，否则大图又会被压小。配置集中在 `wiki-init.js` 的 `mermaid.initialize()`。

### 7.3 画布的点击抑制不要删

见 §3.2。删掉后拖拽会误触发图内链接跳转。

### 7.4 Git 输出中文文件名被转义

`git status` 默认把中文路径显示成 `\345\276\256...`，导致用 PowerShell 处理路径失败。加 `-c core.quotepath=false` 即可。

### 7.5 PowerShell 读文件内容受限

按仓库规则，`Get-Content` 不带 `-Encoding` 会被拦截。处理文本请用编辑工具或 Node 脚本。

### 7.6 文档与实现不一致的记录（wiki 中已按实际实现绘制）

1. `doc/0924` 引用的目标工程 `D:\FPGA_PRO\llme_SDWeight_proj` 不存在
2. `AXU9EGB_MODULE16_BOARD_BRINGUP_PLAN.md` 写的是 `realFpga/vitis_app/lwip_lm_head_raw_server.c`，实际在 `realFpga/vitis/workspace/lm_head_net_diag/src/`
3. 单元测试有两个口径：`unittest discover` 为 10/10，单个 `test_lm_head_cpu_reference.py` 为 6/6
4. 板卡 IP 文档中同时出现 `192.168.8.190`（实际在用）与 `192.168.1.10`（规划示例）

### 7.7 两个高风险的数值口径，改动代码前必读

- **argmax 必须在 FP16 上做**：step 7 的 token 100013 与 100048 转 FP16 后同分（`20.203125`），必须按 `torch.argmax` 规则取较小 ID
- **两类 logits 不能混用**：step 目录下的 `lm_head_vocab_logits.npy` 是 FP16 raw logits（不含 penalty）；`generation_token_vocab_logits/` 是 FP32 processed scores（含 penalty 1.1）
