7. 上板部署（realFpga）

本篇介绍如何把模块 16（LM Head + Argmax）真正跑在 AXU9EGB 开发板上。对应代码目录为 realFpga/，主要参考文档为 realFpga/AXU9EGB_MODULE16_BOARD_BRINGUP_PLAN.md（上板计划）与 realFpga/DEBUG_LOG.md（67 篇调试日志，6240 行）。

7.1 目标与总体路线

项目说明
目标板卡AXU9EGB 开发板（XCZU9EG-2FFVB1156I，Zynq UltraScale+ MPSoC）
工具版本Vivado / Vitis 2021.1
软件路线A53 standalone 裸机 + lwIP raw TCP
PS 配置来源复用同事 RMSNorm 工程已验证的 PS 配置
设计原则：控制通道与数据通道分离——控制通道走 M_AXI_HPM0_FPD → AXI-Lite 配置 HLS 寄存器；数据通道走 HLS 4×m_axi → S_AXI_HP0_FPD → PS DDR4 搬运 hidden/weight/history/logits。

7.4 Vivado Block Design

BD 名称为 lm_head_system，IP 清单如下：

IP 实例作用
zynq_ultra_ps_e_0Zynq UltraScale+ PS
lm_head_argmax_0HLS IP（VLNV xilinx.com:hls:lm_head_argmax:1.0）
axi_smc_ctrlSmartConnect（1S1M），控制通路
axi_smc_memSmartConnect（4S1M），数据通路
rst_ps8_0_100Mproc_sys_reset 复位模块
const_zero / const_onexlconstant 常量

控制通路与数据通路

控制通路：PS M_AXI_HPM0_FPD → axi_smc_ctrl → HLS s_axi_control
          （基地址 0xA0000000，64KiB）

数据通路：HLS 4×m_axi（gmem_hidden / gmem_weight / gmem_history / gmem_logits，各 32bit）
          → axi_smc_mem → PS S_AXI_HP0_FPD → PS DDR
          （HP0 映射 DDR_LOW 2G + DDR_HIGH 32G）

时钟与复位

  • 时钟：单一时钟域 pl_clk0（请求 100MHz，实际 99.999001MHz）驱动所有 AXI / HLS / 复位；HLS 按 200MHz 综合、100MHz 安全运行。
  • 复位：pl_resetn0 → ext_reset_in；interconnect_aresetn → 两个 SmartConnect；peripheral_aresetn → HLS ap_rst_n。
  • 中断：HLS interrupt 有意不接，改用轮询 ap_done。

PS 配置

  • 33.333MHz 参考时钟；DDR4-1600J 4GB 64-bit，训练全开，ECC 关。
  • GEM3 RGMII（MIO64-75）+ MDIO（MIO76-77）；UART0（MIO42-43）；TTC0。
  • 与同事 RMSNorm 工程对齐 1111 项 PSU 参数（1110 项一致）；psu_ddr_init_data() 共 523694 字符，逐字节一致。

7.5 Vitis PS 端软件

软件位于 vitis/workspace/lm_head_net_diag/src/，由三个关键部分组成：

main.c：启动流程

platform 初始化
  → DDR smoke test（0x10000000，4096 字写读 + Cache flush/invalidate，过了才起网络）
  → lwip_init
  → 静态 IP 192.168.8.190（无串口交互，printf 仅走 UART）
  → 主循环：xemacif_input + TCP 定时器

lwip_lm_head_raw_server.c（1179 行，核心）

  • LMH1 TCP server，端口 19016，单连接多帧状态机：跨 pbuf 拼帧、响应发完复位帧状态、权重跨连接保留。
  • 流式权重接收：单块最大 16MiB，直写 DDR 预留区并立即 Xil_DCacheFlushRange。
  • 收到 RUN_TOKEN 时：配置 HLS 寄存器（地址 / hidden_size / vocab_size / write_logits / penalty 开关与数值）→ XLm_head_argmax_Start + 轮询 IsDone（超时保护 1e9 次）→ Xil_DCacheInvalidateRange 读回 logits / token / score → 4KiB 分段 tcp_write + tcp_sent 回调回传。

lmh_buffers.h + lscript.ld：PS DDR NOLOAD 布局

缓冲区大小
weight272269312 B
hidden1792 B
history18992 B
logits303872 B
网络 RX 缓冲1 MiB

全部 64B 对齐，通过链接脚本以 NOLOAD 方式预留，避免与裸机程序其它段冲突。

7.7 调试经验精选（来自 DEBUG_LOG 67 篇）

最大的坑：首次上板一启动 HLS 就 AXI / DAP 锁死、ping 消失。根因有两层——
  • 复位拓扑错误（interconnect_aresetn / peripheral_aresetn 混接）；
  • proc_sys_reset 的 aux_reset_in 是低有效（C_AUX_RESET_HIGH=0），而 BD 接了 const_zero，导致 SmartConnect 和 HLS 永久复位。
修复：改接 const_one；并改进下载顺序（psu_init → 配置 PL → 解除 PS-PL isolation → 用 AXI-Lite 无启动预检读 AP_CTRL → 下 ELF），用 force-mem-accesses 预检区分「控制口不响应」与「数据口出错」。修复后 AP_CTRL 读回 0x4（ap_idle）正常。
Vitis HLS 2021.1 的年代问题：在 2026 年，core_revision 的 32-bit 有符号溢出会导致 IP 打包失败，需用 run_export_ip_2021_compat.ps1 兼容脚本 + Vivado 重打包。并且 vitis_hls.bat 的退出码不可信（内部失败仍返回 0），必须检查 component.xml 是否实际生成。
其它常见误判与陷阱：
  • 误判 PS DDR 未启用：看 USE__DDR_INTF_REQUESTED=0 就判定 DDR 关闭是错的。
  • Vitis IDE 构建「假成功」（ELF 缺失）：改用 Makefile 构建并验证 ELF 存在。
  • PHY 通用识别补丁（xemacpsif_physpeed.c）打入 BSP 后，bsp regenerate 会覆盖补丁，需要重打；lwIP 参数需调大（mem_size 262144、tcp_snd_buf/wnd 32768、memp_num_tcp_seg 512）。
  • 逐级放大策略：4×4 → vocab 128 / 1024 / 8192 / 65536 → 完整 151936，每一级都留证据，出问题能快速定位到刚放大的那一级。
