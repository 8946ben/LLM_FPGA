两个反复出现的陷阱

陷阱一：argmax 必须在 FP16 上做。 step 7 中 token 100013 与 100048 的 FP32 累加值不同，转 FP16 后同为 20.203125。 必须按 torch.argmax 规则选位置靠前的 100013；在 FP32 累加器上做 argmax 会选错。
陷阱二：平分判定与 processed score。 argmax 必须使用 penalty 之后的分数，且 token_id == 0 时无条件初始化， 保证「分数相同保留较小 token ID」。板卡实测也验证了开关确实到达硬件： 关闭时 selected_score = 30.046875，开启 penalty = 1.1 时为 27.315340042114258（≈ 30.046875 / 1.1）。
